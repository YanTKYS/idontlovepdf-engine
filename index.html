PDF本文編集エンジン 検証コンソール

  • 自作PDF本文編集モジュール（src/）の検証用画面です。一般職員向けの完成UIではありません。
  • PDF本体はこのブラウザ内だけで処理します。
  • GitHub、外部API、その他サーバーへのPDF送信は行いません。
  • 現在はPoC（試作）段階です。
  • 一般的なPDFすべてへの対応は保証しません。失敗するPDFがあることが前提の検証ツールです。

プライバシー: 選択したPDFはこのブラウザ内で処理されます。本ツールからGitHub、外部API、その他サーバーへのPDF送信は行いません。画面表示（HTML / CSS / JavaScript）のみGitHub Pagesから配信され、PDFの中身はFile → ArrayBuffer → Uint8Array として端末内で完結します。編集結果の保存もブラウザのダウンロード機能によるローカル保存です。

実装上も、外部CDN・外部フォント・外部APIを使わず、fetch() / XMLHttpRequest / WebSocket を一切含みません。

PDFを1件選択すると、PdfTextEditor を初期化し listTextRuns() の結果を一覧表示します。続けてrunを1件選び、日本語などへの置換を試せます。

PDFファイルを1件選択、またはここへドラッグ＆ドロップ

選択したファイルは送信されません。

本文run一覧

text はfontの /ToUnicode CMapによる復号結果です。復号できない箇所は U+FFFD として表示され、そのrunに「復号不可を含む」と表示します（画面全体は停止しません）。 bytes は既定で先頭12バイトのみを表示し、「詳細」で全体を表示します。

選択 id objectNumber fontName text 文字数 bytes数 bytes (hex)

日本語置換テスト

例: 元テキスト 令和8年度 → 置換後 令和9年度。 置換は元PDFのバイト列の複製に対して行い、replaceText() → save() の結果を 元ファイル名.edited.pdf としてローカル保存します。元のPDFファイルは変更しません。

置換にはCMapの逆引きが必要です。CMapに存在しない文字（既存fontにglyphがない文字）を指定すると失敗します。 失敗内容はエラー原文つきで表示し、元PDFが変更されていないことも併せて表示します。

複数のPDFを選択し、Node版 scripts/assess-corpus.js と同じ段階（load / extract / writeback / save / reopen）で一括評価します。

writebackMode: same-bytes

writeback: true は「別文字への置換に成功した」という意味ではありません。 最初のrunに元と同じbytesを書き戻し、置換から保存までの経路だけを検査しています。 「日本」→「沖縄」のような別文字への置換可否は、単一PDF検証タブで文書ごとに確認してください。

readerDisplay は自動判定しません（常に null）。Acrobat Reader等の独立したPDF readerでの表示確認は人間が行ってください。

選択したファイルは送信されません。すべてこのブラウザ内で評価します。

一括評価結果

○ 成功 / × 失敗 / - 未実施。失敗した段階より後ろは「- 未実施」です。編集済PDFは行ごとに手動で保存します（自動ダウンロードはしません）。

PDF load extract writeback save reopen runs error 編集済PDF

assessment.json には各PDFの file / load / extract / writeback / writebackMode / save / reopen / runCount / readerDisplay / error を記録します。readerDisplay は独立readerで確認したうえで手動追記してください。

判別できる主な失敗理由

エラーは分類ラベルと原文の両方を表示します。次のような原因を区別できます。

  • xref stream未対応 / object stream未対応の可能性
  • 暗号化PDF / unsupported filter（未対応の圧縮・符号化）
  • 本文runなし（テキストが画像化されている場合を含む）
  • ToUnicodeなし / CMap逆引き失敗（glyph不足の可能性）
  • 保存失敗 / 再読込失敗
